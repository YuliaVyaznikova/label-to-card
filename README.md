# label-to-card

Решение кейса «Своё Родное» стипендиальной программы РСХБ 2026-2027, задача «Карточка товара за три минуты».

Фермер фотографирует упаковку, сервис собирает черновик карточки товара для маркетплейса, в которой указаны категория, название, состав, масса, срок годности, условия хранения, изготовитель, пищевая ценность и описание. Затем он показывает, что осталось заполнить, проверяет карточку по правилам модерации, а фермер правит её и подтверждает. Система не выдумывает факты сама, значение попадает в карточку, только если его текст найден на фото или в словах фермера, иначе поле остаётся пустым и сервис просит дописать его.

## Как устроено решение

1. **Проверка фото.** Размер, резкость, освещённость (OpenCV) и наличие на снимках этикетки с составом.
2. **Распознавание текста.** RapidOCR с моделями PP-OCRv5 (детектор и распознаватель для восточнославянских языков) на ONNX Runtime (работает на CPU). Фрагменты одного ряда склеиваются в строки, повёрнутые снимки распознаются после поворота.
3. **Категория.** Zero-shot классификация SigLIP 2 по фото плюс ключевые слова из распознанного текста.
4. **Извлечение полей.** Qwen3-VL-235B-A22B через API Polza AI получает фото, распознанный текст с номерами строк и слова фермера. По каждому полю модель возвращает дословную цитату, номера строк и источник (фото, фермер или нет данных). Модель выбрана замером из трёх Qwen3-VL, подробности в разделе «Результаты».
5. **Проверка без выдумок.** Значение разбирается собственным парсером из цитаты, а не берётся из ответа модели. Текстовое поле принимается, если цитата нашлась в распознанном тексте нечётким сравнением (rapidfuzz), состав ещё и только если он указан рядом со словом «Состав». Числовое поле принимается, если значение напечатано на фото со своим признаком (калорийность рядом с «ккал», масса с единицей измерения, белки, жиры и углеводы после своего названия или в соседней строке таблицы). Сравнение прощает типичные ошибки распознавания (латинские буквы вместо кириллицы, «*уры» вместо «жиры»), но не исправляет их. Не прошедшее проверку поле становится пустым и попадает в журнал проверки с указанием причины. Если масса на этикетке расходится с массой со слов фермера, карточка блокируется до исправления.
6. **Описание.** Модель пишет описание только по проверенным полям, затем код проверяет, что в тексте нет чисел и утверждений («натуральный», «лечит» и подобных), которых нет в фактах. После двух неудачных попыток описание собирается по шаблону.
7. **Готовность и модерация.** Готовность от 0 до 100: 60 баллов за обязательные поля, 20 за фото, 20 за название и описание. Правила модерации блокируют контакты, медицинские обещания и расхождение этикетки со словами фермера, а также предупреждают о рекламных утверждениях без подтверждения, заглавных буквах, цене и эмодзи в названии, несоответствии категории и ветеринарных документах для продуктов животного происхождения.
8. **Правка и подтверждение.** Фермер видит фото с подсветкой места, из которого взято каждое значение, правит поля, досылает фото и подтверждает карточку, после чего видит её такой, какой её увидят покупатели. Подтверждённая карточка отдаётся площадке через API в JSON, у каждого поля указаны источник и место на фото.

Обязательные поля взяты из статьи 4.1 ТР ТС 022/2011 «Пищевая продукция в части её маркировки», состав полей по категориям лежит в `categories.yaml`.

## Результаты

Сервис проверен на 120 товарах из Open Food Facts. Этот набор данных представляет из себя русские этикетки, снимки пользователей сайта, у каждого товара отдельные фото лицевой стороны, состава и пищевой ценности. Как итоговый вариант выбрана модель Qwen3-VL-235B-A22B. Сравниваются три способа:

- **Модель без проверки** получает фото и сама заполняет карточку, а если сведений нет, пишет null.
- **Извлечение без проверки** - наш промпт с распознанным текстом, значения берутся из ответа модели как есть.
- **Сервис целиком** - извлечение и проверка по фото.

Главный вопрос в том, что происходит, когда нужных сведений на фото нет. Поэтому каждый товар прогоняется ещё раз только с фото лицевой стороны. Состава и пищевой ценности на нём нет, и любое заполненное значение этих полей выдумано. Товары, на лицевой стороне которых есть слова «состав», «белки», «углеводы» или «ккал», из этого подсчёта исключены, остаётся 556 скрытых полей.

| | Модель без проверки | Извлечение без проверки | Сервис целиком |
|---|---|---|---|
| Выдумано, только лицевая сторона | 13.5% (8.3-19.0) | 8.1% (5.1-12.0) | **0.4% (0-0.9)** |
| Precision, все фото | 0.875 (0.849-0.898) | 0.847 (0.821-0.875) | 0.856 (0.826-0.885) |
| Recall, все фото | 0.832 (0.810-0.856) | 0.774 (0.743-0.806) | 0.558 (0.519-0.599) |

Precision здесь означает долю заполненных значений, совпавших с данными Open Food Facts, а recall - долю значений из Open Food Facts, которые заполнены верно. В скобках 95% доверительный интервал бутстрепа по товарам.

Когда сведений на фото нет, модель без проверки заполняет каждое седьмое такое поле правдоподобным типичным значением, и отличить его от настоящего нельзя: у молока 58 ккал и 1.5 г жиров вместо 63 ккал и 3.5 г, у соевого соуса 8 г белков вместо 3.5 г. Сервис оставляет такие поля пустыми и просит фермера их дописать. Две его ошибки взяты с лицевой стороны, но не на 100 г: «20 г 41 ккал» у сметаны это порция, «500 g (3,425 kcal)» у майонеза это вся упаковка.

Precision у сервиса такой же, как у модели без проверки, а recall ниже, потому что значение принимается, только если распознавание текста нашло его на фото. Пропуски в основном там, где текст на снимке не распознался, т.е. где есть тень на изгибе упаковки, мелкий или повёрнутый шрифт, блик. Такие поля сервис отмечает как пустые и предлагает досъёмку.

| Поле | Precision | Recall |
|---|---|---|
| Название | 0.77 | 0.68 |
| Состав | 0.83 | 0.58 |
| Масса или объём | 0.70 | 0.27 |
| Энергетическая ценность | 0.92 | 0.66 |
| Белки | 0.89 | 0.54 |
| Жиры | 0.90 | 0.62 |
| Углеводы | 0.94 | 0.56 |

Это сравнение для результатов режима "Сервис целиком" на всех фото. Название сравнивается с названием в Open Food Facts, которое набирают пользователи сайта, поэтому его precision занижен. Массу часто печатают на крышке или крупным стилизованным шрифтом, отсюда её низкий recall.

На странице `data/eval/gallery.html` собраны все 120 товаров с фото, значениями из Open Food Facts, ответом модели без проверки и итогом сервиса, а также с тем, что каждый способ заполнил, когда видел только лицевую сторону. Страница открывается в браузере, фото подгружаются с сайта Open Food Facts.

**Выбор модели.** Три модели Qwen3-VL сравнивались на первых 30 товарах.

| Модель | Выдумано без проверки | Выдумано сервисом | Recall сервиса | Стоимость использования API за 1 товар |
|---|---|---|---|---|
| Qwen3-VL-8B | 8.5% | 0.7% | 0.53 | 0.23 ₽ |
| Qwen3-VL-30B-A3B | 52.1% | 0.7% | 0.57 | 0.15 ₽ |
| Qwen3-VL-235B-A22B | 9.9% | 0.7% | 0.59 | 0.30 ₽ |

С проверкой все три модели выдумывают одинаково мало, даже 30B-A3B, которая без проверки заполняет половину скрытых полей. Выбрана 235B, потому что у неё лучший recall, а разница в цене меньше 0,1 рубля на товар. Черновик собирается меньше чем за минуту на ноутбуке без видеокарты, около 25 секунд из них занимает ответ модели. Вся оценка стоила около 120 ₽.

## Установка

```
python -m venv .venv
.venv/Scripts/pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.venv/Scripts/pip install -r requirements.txt
cd web
npm install
npm run build
```

Проверено на Python 3.14 и Node 24. Видеокарта не нужна, распознавание текста и классификатор работают на процессоре. В Linux и macOS путь к pip `.venv/bin/pip`.

Ключ API Polza AI кладётся в файл `.env` в корне репозитория (образец в `.env.example`):

```
POLZA_API_KEY=...
```

## Запуск

```
.venv/Scripts/python -m uvicorn card.api:app --port 8000
```

Интерфейс открывается по адресу http://127.0.0.1:8000/. Для разработки интерфейса `npm run dev` в папке `web` запросы к API проксируются на порт 8000. Модели распознавания и классификации загружаются при старте сервера, первый запуск скачивает их веса (около 1.5 ГБ).

Тесты:

```
.venv/Scripts/python -m pytest
```

## API

Контракт в `openapi.yaml`, он же по адресу http://127.0.0.1:8000/docs.

| Метод | Назначение |
|---|---|
| `POST /v1/drafts` | создаёт черновик из 1-5 фото (JPEG или PNG до 10 МБ) и слов фермера `hints`, поддерживает заголовок `Idempotency-Key` |
| `GET /v1/drafts/{id}` | черновик: поля с источниками и местом на фото, описание, готовность, что осталось сделать, замечания модерации, журнал проверки |
| `PATCH /v1/drafts/{id}/fields` | правка полей, категории и описания фермером |
| `POST /v1/drafts/{id}/photos` | досъёмка (добавляет фото и пересобирает черновик, правки фермера сохраняются) |
| `POST /v1/drafts/{id}/confirm` | подтверждение, возвращает 409, если есть блокирующие замечания или пустые обязательные поля |
| `GET /v1/categories` | список категорий |
| `GET /v1/categories/{key}/schema` | поля категории |

## Оценка

```
.venv/Scripts/python -m evaluation.off images 120
.venv/Scripts/python -m evaluation.run --set off --limit 120 --name full
.venv/Scripts/python -m evaluation.report --name full
.venv/Scripts/python -m evaluation.gallery --name full
.venv/Scripts/python -m evaluation.run --set off --limit 30 --models qwen/qwen3-vl-8b-instruct,qwen/qwen3-vl-30b-a3b-instruct,qwen/qwen3-vl-235b-a22b-instruct --name models
```

| Шаг | Назначение | Результат |
|---|---|---|
| `evaluation.off images` | скачивает фото товаров из `data/off/manifest.json` (около 400 МБ) | `data/off/images` |
| `evaluation.run` | прогоняет три способа на всех фото и только на лицевой стороне, около 40 минут и 70 ₽ на 120 товаров | `data/eval/<name>`: ответы, `metrics.csv`, `fields.csv`, `usage.csv` |
| `evaluation.report` | 95% доверительные интервалы бутстрепом по товарам | `data/eval/<name>/report.csv` |
| `evaluation.gallery` | страница с фото и ответами по каждому товару | `data/eval/gallery.html` |

Список товаров уже лежит в `data/off/manifest.json`. Чтобы собрать его заново (результаты поиска Open Food Facts меняются со временем), есть `python -m evaluation.off search 10` и `python -m evaluation.off select 200`. Ответы модели кэшируются в `data/cache`, повторный прогон с тем же кодом ничего не стоит.

## Структура проекта

| Директория/файл | Содержание |
|---|---|
| `card` | сервис: проверка фото, распознавание, классификация, извлечение, проверка, описание, готовность, модерация, хранилище черновиков, API |
| `web` | интерфейс фермера на React, TypeScript, Vite и Tailwind |
| `evaluation` | загрузка данных Open Food Facts, прогон методов, метрики и страница с результатами по товарам |
| `tests` | тесты разбора значений, проверки цитат, распознавания и правил |
| `categories.yaml` | категории и поля карточки |
| `config.yaml` | параметры моделей и порогов |
